# AI анализатор видеовстреч

Проект выполняет задания Lite и Pro урока 7 и продолжает приложение из `Lesson_02`. Он принимает короткие видеозаписи WebM и MP4, автоматически распознаёт речь, формирует структурированный AI-конспект и сохраняет результат в панели аналитики.

## Реализовано

### Lite

- раздел «Входящие записи» для WebM и MP4 до 500 МБ и 5 минут;
- проверка контейнера, наличия видео- и аудиодорожки через FFprobe;
- автоматический pipeline «Загружен → Распознавание речи → AI-анализ → Готово»;
- краткое содержание, темы, решения, задачи и открытые вопросы;
- сохранение исходника, расшифровки, статусов и результата в SQLite;
- панель со счётчиками, последними встречами, источником и подробной карточкой;
- понятный статус ошибки с возможностью повторить обработку.

### Pro

- импорт по публичной прямой HTTPS-ссылке без OAuth;
- поддержка прямых ссылок на WebM и MP4;
- защита от локальных и приватных адресов, небезопасных схем, лишних перенаправлений и файлов больше 500 МБ;
- сообщение о необходимости ручной загрузки, когда облако требует авторизацию;
- ручная загрузка и облачный импорт используют один pipeline;
- повторная нормализованная ссылка открывает существующую встречу вместо нового анализа;
- SHA-256 сохраняется вместе с импортированным файлом;
- на панели различаются источники «Загружено вручную» и «Из облака».

## Локальный режим

Локальный профиль полностью автономен: SQLite и исходники находятся в `data/`, распознавание выполняет локальный Whisper, анализ — локальный Ollama. На Ubuntu с FFmpeg, FFprobe и рабочим NVIDIA GPU:

```bash
./scripts/setup.sh
./scripts/download-models.sh
./scripts/run.sh
```

Откройте `http://127.0.0.1:8765`. Данные сохраняются в `data/`. Для другого каталога задайте `MEETINGS_DATA`.

Если окружение и модели уже подготовлены, достаточно:

```bash
./scripts/run.sh
```

`MEETINGS_RUNTIME` по умолчанию имеет значение `local`. Облачные ключи для этого режима не нужны. Полный набор локальных Python-зависимостей перечислен в `requirements-local.txt`, а воспроизводимый снимок — в `requirements.lock.txt`.

## Vercel-режим

Публикация является отдельным deployment-профилем и не заменяет локальную установку:

- FastAPI и статический интерфейс работают в Vercel Functions;
- записи загружаются браузером прямо в приватный Vercel Blob;
- метаданные, очередь и результаты сохраняются в Turso SQLite;
- транскрипция и структурированный анализ выполняются через Vercel AI Gateway;
- `MEETINGS_RUNTIME=vercel` включает облачные адаптеры, локальный профиль при этом не изменяется.

Интерактивная настройка:

```bash
./scripts/vercel-setup.sh
```

Мастер не выполняет `git push`. Он связывает уже опубликованный GitHub-проект с Vercel, помогает подключить приватный Blob, Turso и AI Gateway, затем запускает Preview и — только после подтверждения — Production deployment.

Для импорта monorepo в Vercel укажите Root Directory `Lesson_07`. Если проект создаётся CLI из этой папки, root определяется автоматически.

## Использование

1. На панели выберите WebM или MP4 в блоке «Входящие записи». Анализ начнётся автоматически.
2. Для Pro вставьте публичную прямую ссылку в «Добавить по ссылке». Ссылка на страницу предварительного просмотра может не подойти.
3. Следите за текущим этапом в карточке встречи.
4. После статуса «Готово» проверьте расшифровку и структурированный результат.

## Проверки

```bash
.venv/bin/python -m pytest -q tests/
.venv/bin/python -m py_compile app/*.py
node --check app/static/app.js
```

В ограниченной агентской среде `TestClient` исходного проекта может зависать. Поэтому новые Lite/Pro-сценарии дополнительно проверяются прямыми сквозными smoke-тестами БД, pipeline и дедупликации; результаты описаны в `TEST_REPORT.md`.

## Профили зависимостей

- `requirements.txt` — компактный Python-набор для Vercel и общих функций;
- `requirements-local.txt` / `requirements.lock.txt` — локальные Whisper, CUDA и тестовые инструменты;
- `package.json` — Vercel Blob, AI Gateway и Turso для облачных функций;
- `.env.example` — явное разделение локальных и облачных переменных.

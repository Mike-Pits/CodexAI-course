# Публикация на VPS: пошаговый маршрут

Локальная Ubuntu: 24.04.4 LTS. VPS по исходным данным: Ubuntu 20.04. Домен ещё не выбран. На VPS уже установлен Docker 26.1.3; Compose отсутствует. Порт 443 занят Xray, также работает контейнер amnezia-awg. Их сохраняем. Для приложения выбран HTTPS-порт 8443; порты 80 и 8443 проверены и свободны. Приложение пока не опубликовано.

## 1. Проверить VPS до изменений

Подключитесь своим обычным SSH-пользователем. Не передавайте приватный SSH-ключ, пароль или OpenAI-ключ в чат. Соберите:

```bash
cat /etc/os-release
uname -m
free -h
df -h /
command -v docker
sudo ss -lntp
sudo ufw status verbose
pro status
apt-cache policy docker.io docker-compose-v2 docker-ce docker-compose-plugin
```

**Контрольная точка Ubuntu 20.04:** стандартная поддержка завершилась 29 мая 2025; необходима проверка ESM и покрытия пакетов. Текущая документация Docker не включает 20.04 в поддерживаемые Ubuntu. Не запускайте автоматический установщик Docker и не подключайте репозиторий другой версии Ubuntu. По результатам проверки нужно выбрать поддерживаемый путь установки/обновлений; пока этот шаг не решён, публичное развёртывание отложено. ОС автоматически не обновляем и не переустанавливаем.

Источники:
- https://lists.ubuntu.com/archives/ubuntu-security-announce/2025-May/009421.html
- https://docs.docker.com/engine/install/ubuntu/

## 2. Подготовить Docker и доступ

После решения контрольной точки установите Docker Engine и Compose по подходящему официальному руководству. Проверки: `docker version` и `docker compose version`. Если текущий пользователь не имеет прав Docker, используйте `sudo`; членство в группе docker даёт привилегии уровня root.

В сетевом экране провайдера и UFW сохраните **фактический SSH-порт** и откройте TCP 80/8443. Не включайте UFW до разрешения SSH. После настройки проверьте новый SSH-сеанс, оставив старый открытым. Docker публикует только 80/8443 через Caddy, порт 8000 не открывать.

## 3. Домен и DNS

Зарегистрируйте домен в своём аккаунте. Можно использовать поддомен `chat.ваш-домен`.

- Создайте A-запись выбранного имени → публичный IPv4 VPS.
- AAAA добавляйте только при настроенном IPv6; ошибочная AAAA мешает HTTPS.
- Для первого запуска используйте прямой DNS без CDN-проксирования.
- Проверьте разрешение имени командой `getent ahosts chat.ваш-домен`.

## 4. Загрузить проект и настроить ключ

Локально создайте архив `python3 scripts/package.py`. Передайте его по SCP на VPS и распакуйте в отдельную папку, например `~/tochka-opory`. Команда имеет вид `scp dist/tochka-opory-lesson01.zip USER@VPS:~/`; замените USER и VPS на реальные значения. Архив содержит верхнюю папку `tochka-opory`.

На VPS внутри проекта:

```bash
cp -n .env.example .env
chmod 600 .env
python3 -c 'import secrets; print(secrets.token_hex(32))'
nano .env
```

Заполните `LLM_BASE_URL`, `LLM_API_FORMAT`, `LLM_API_KEY`, `LLM_MODEL`, `QUOTA_SECRET`, `DOMAIN` (без схемы), `ACME_EMAIL` и `PUBLIC_ORIGIN=https://выбранный-домен:8443`. Установите `CHAT_MODE=llm` для настоящей модели или `mock` для готовых ответов. Email используется для ACME-сертификата. Не показывайте `.env` в логах или скриншотах. Ключ передаётся только приложению, контейнер Caddy его не получает.

Проверить доступ к API именно с VPS можно скриптом внутри образа:

```bash
docker compose build app
docker compose run --rm -T --no-deps app python - --models < scripts/check_llm.py
docker compose run --rm -T --no-deps app python - --probe < scripts/check_llm.py
```

Первый вызов читает список моделей, если провайдер поддерживает `/models`. Для второго задайте доступную модель; он делает один небольшой потенциально платный запрос. При отказе по региону или правам остановитесь и выясните причину. Выбор модели ещё не проверен для вашего ключа.

## 5. Запуск и проверка

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=50
```

Caddy получит сертификат через HTTP-01 при корректном DNS и доступном извне TCP 80. Проверка TLS-ALPN на 443 отключена, поскольку этот порт использует Xray. Пользователи открывают сайт на HTTPS-порту 8443; HTTP перенаправляется на этот же порт. DOMAIN указывается без номера порта. Правила для Xray, ZeroTier и Amnezia не менять. Откройте `https://ваш-домен:8443` и `/api/health`. Убедитесь, что HTTP перенаправляет на HTTPS, сертификат действителен, запросы к чату работают. Пройдите `CHECKS.md`.

Проверьте `docker compose restart`, затем доступность сайта и сохранение счётчика. Полную перезагрузку VPS выполняйте отдельно, когда не осталось других работ на сервере; после неё проверьте автозапуск Docker и сайта. Проверка процесса healthcheck не проверяет баланс или доступность OpenAI.

## 6. Обновление и остановка

Сохраните предыдущий архив, `.env` и volume квот. Обновите исходники, не перезаписывая `.env`, затем `docker compose up -d --build`. При ошибке верните предыдущие исходники и повторите сборку. Не используйте `down -v`: это удалит счётчики и сертификаты.

Остановка: `docker compose down`. Просмотр ошибок: `docker compose logs --tail=50 app`. В приложении нет журналирования переписки; не включайте отладочные логи HTTP-клиента в публичной версии. Для изменения сведений отредактируйте `app/business.json` и пересоберите образ.

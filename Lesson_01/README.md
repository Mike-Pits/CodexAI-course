# Точка опоры — домашняя работа Codex_AI, урок 01, Light

Учебный AI-администратор вымышленного сервиса психологической поддержки. Чат отвечает об услугах, ценах, расписании и порядке обращения. Реальной записи, оплаты, регистрации и терапии нет.

## Запуск на локальной Ubuntu 24.04

### Настройки провайдера

Поддерживаются OpenAI-совместимые API с Bearer-ключом: Chat Completions и Responses. Нативные API с другим протоколом (например, Anthropic Messages или Gemini generateContent) требуют отдельного адаптера.

Для VseLLM в `.env` уже подготовлены `LLM_BASE_URL=https://api.vsellm.ru/v1` и `LLM_API_FORMAT=chat_completions`. Заполните `LLM_API_KEY` ключом VseLLM и `LLM_MODEL` точным ID из его каталога (префикс производителя является частью ID). Затем переключите `CHAT_MODE=llm` и перезапустите приложение. Пока значения не заполнены, оставьте `CHAT_MODE=mock`.

`LLM_BASE_URL` — базовый URL, обычно с `/v1`, без `/chat/completions` или `/responses`. `LLM_TOKEN_PARAMETER` выбирает `max_tokens` либо `max_completion_tokens` для Chat Completions. `LLM_REASONING_EFFORT` необязателен: оставьте пустым, если модель не поддерживает параметр.

Для прямого OpenAI укажите `LLM_BASE_URL=https://api.openai.com/v1`, `LLM_API_FORMAT=responses` и соответствующие ключ/модель. Старые `OPENAI_*` используются только при полном отсутствии `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`. При наличии новых настроек даже пустой `LLM_API_KEY` не подставляется из старого ключа: секрет OpenAI не будет отправлен другому сервису автоматически.

Документация VseLLM: https://vsellm.ru/docs. Доступ с вашим ключом ещё не проверен.

Из папки `Lesson_01` (Python 3.12):

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp -n .env.example .env
chmod 600 .env
python3 -c 'import secrets; print(secrets.token_hex(32))'
nano .env
```

В `.env` заполните настройки `LLM_*` выше и `QUOTA_SECRET` (последний — результат генерации выше). Ключ не отправляйте в переписку. Если провайдер поддерживает `/models`, запросите список:

```bash
.venv/bin/python scripts/check_llm.py --models
```

Выберите текстовую модель с поддержкой выбранного формата API. Впишите ID в `LLM_MODEL`, установите `CHAT_MODE=llm`. Затем выполните один небольшой потенциально платный запрос (он выполняется даже при `CHAT_MODE=mock`):

```bash
.venv/bin/python scripts/check_llm.py --probe
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers --no-access-log
```

Откройте http://127.0.0.1:8000. Без ключа/модели интерфейс открывается, отправка показывает «Чат ещё настраивается». Перезапустите сервер после изменения `.env`, базы знаний или инструкций.

Локальный вариант в Docker, после заполнения `.env`:

```bash
docker compose -f compose.local.yaml up -d --build
docker compose -f compose.local.yaml logs --tail=30
docker compose -f compose.local.yaml down
```

## Устройство

- `app/static/`: адаптивный интерфейс без сборки и сторонних CDN.
- `app/main.py`: FastAPI; `app/llm.py`: формирование запросов и разбор ответов настроенного LLM-провайдера через httpx.
- `app/business.json`, `app/prompt.txt`: редактируемые сведения и правила администратора.
- `app/limits.py`: атомарные квоты в SQLite, без хранения сообщений. Это технический счётчик, не база пользователей.
- `POST /api/chat`: `{ "message": "Сколько стоит?", "history": [{"role":"user", "content":"..."}, {"role":"assistant", "content":"..."}] }` → `{ "reply": "..." }`.
- `GET /api/services?max_price_rub=3000`: возвращает демонстрационные форматы, цена которых не превышает выбранный бюджет. Интерфейс использует этот endpoint для фильтра по бюджету.
- `GET /api/health`: работоспособность процесса и наличие настройки ключа/модели; **не** проверка доступности OpenAI.

До 1500 символов в новом вопросе; 8 сообщений и 12000 символов истории; HTTP-тело до 64 КиБ. Лимит ответа задаётся MAX_OUTPUT_TOKENS (по умолчанию 600), включая внутренние токены рассуждения. Для выбранного gpt-5.6-sol с OPENAI_REASONING_EFFORT=medium в локальном .env установлен лимит 2000; качество ответов ещё предстоит проверить после пополнения API-баланса. История хранится только в памяти страницы. Ответы выводятся как текст, без выполнения HTML.

## Данные и ограничения

Сообщения не записываются в файлы, SQLite или логи приложения; access-log Uvicorn выключен. В режиме llm вопрос и последние сообщения передаются выбранному провайдеру. Для Responses отправляется `store: false`; для совместимости Chat Completions параметр `store` не передаётся. Политика хранения данных определяется провайдером: отсутствие локальной истории не гарантирует отсутствие хранения у него. Настройки URL и ключа доступны только владельцу сервера; браузер не может их менять.

Скользящий лимит — 5 обращений за 60 секунд на IP; общий — 100 в сутки по UTC, включая неудачные запросы к провайдеру. До запроса атомарно резервируется квота. Счётчики переживают перезапуск благодаря Docker volume; **не удаляйте volume для обновления**. Вместо IP хранится HMAC; записи минутного окна очищаются при следующем запросе. Ключ HMAC должен быть стабильным. IP-лимит не распознаёт пользователей за общим NAT; злоумышленник может исчерпать общий бюджет. Это учебное демо, не защита от DDoS и не денежный лимит на аккаунт OpenAI.

За Caddy приложение доверяет только перезаписанному `X-Real-IP`; порт приложения наружу не опубликован. Не включайте `TRUST_CADDY=1` для напрямую доступного сервера. Добавление CDN требует отдельной настройки доверенных прокси.

## Проверки и сдача

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
node --check app/static/app.js
python3 scripts/package.py
```

Архив: `dist/tochka-opory-lesson01.zip`. Сборщик включает только исходники и документацию; `.env`, база квот, окружение и кэши исключены.

Сценарии ручной проверки — в `CHECKS.md`. Публикация — в `DEPLOY.md`. Качество ответов модели нельзя подтвердить mock-тестами; семь реальных диалогов нужно проверить после настройки ключа и выбранной модели.

При ошибке установления соединения клиент делает до двух повторов. Уже отправленные запросы не повторяются. Тайм-аут подключения — 4 секунды на попытку, остальных сетевых операций — 30 секунд. Это помогает при кратковременных сбоях, но не устраняет проблемы маршрутизации или VPN.

## Бесплатные тестовые ответы (без OpenAI)

Установите `CHAT_MODE=mock` в `.env` и перезапустите сервер. Ключ и модель для него не требуются; HTTP-клиент LLM не создаётся. Интерфейс показывает режим и отсутствие передачи данных провайдеру. Готовые ответы выбираются по словам в вопросе; цены и расписание берутся из `business.json`. История не интерпретируется, неизвестные вопросы получают честный шаблонный ответ. Это проверка интерфейса, не качества LLM и не надёжная система распознавания кризиса.

Лимиты запросов и валидация сохраняются. Для настоящей модели заполните настройки провайдера, смените `CHAT_MODE=llm` и перезапустите сервер. Скрипт `check_llm.py --probe` — отдельная явная проверка настоящего API, его не нужно запускать для mock-режима. Без флагов он только проверяет конфигурацию, не отправляя запросов. Старое имя `check_openai.py` перенаправляет в этот же скрипт. Одни только тестовые ответы не закрывают требование домашней работы об обращении к LLM API.

# СУБ Оператор Pro

Полностью локальное независимое приложение с гибридным RAG по полному 57-страничному «Судовому руководству по управлению безопасностью и предотвращением загрязнения». Генерация и embeddings выполняются локальным Ollama. Каждый вопрос автоматически проходит через два поисковых канала: embeddings + cosine similarity и BM25. Результаты объединяются Reciprocal Rank Fusion, дубли удаляются, а top-K фрагментов передаются LLM.

## Быстрый запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python ingest.py
uvicorn app:app --reload --port 8001
```

Откройте <http://127.0.0.1:8001>. В каждом ответе можно раскрыть три диагностических списка: результаты vector search, результаты BM25 и итоговый контекст после RRF.

## Docker

```bash
docker compose run --rm pro-rag python ingest.py
docker compose up --build
```

Интерфейс будет доступен на <http://127.0.0.1:8001>.

## Обновление базы знаний

Кнопка «Обновить индекс» повторно читает файлы из `knowledge/`, создаёт embeddings и атомарно заменяет локальный индекс. Исходный мануал можно повторно извлечь командой:

```bash
python scripts/prepare_kb.py "../СП Судовое рук по СУБ.doc" \
  --soffice /path/to/soffice
python ingest.py
```

Менять программный код после добавления или замены `.md` не требуется.

## Алгоритм поиска

1. Мануал делится по заголовкам на смысловые чанки до 1800 символов с небольшим перекрытием.
2. Для каждого чанка сохраняются источник, раздел, версия `29.10.2021` и уникальный ID.
3. Векторный канал ищет смыслово близкие фрагменты по cosine similarity локальных embeddings `bge-m3`.
4. BM25 независимо ранжирует те же чанки и хорошо поднимает точные обозначения вроде `Д-8`, `Д-9`, `СвУБ`.
5. RRF объединяет ранги двух каналов, удаляет повторения и выбирает три наиболее надёжных фрагмента для LLM.
6. Локальная модель `qwen3:8b` возвращает ответ и ID использованных чанков; UI показывает только подтверждающие источники и полную диагностику поиска.

## Тестирование

```bash
pytest -q
```

Десять end-to-end сценариев находятся в `tests/e2e_questions.json`. Фактические ответы, источники и сравнение поисковых каналов фиксируются в `Отчет_тестирования_Pro.docx`.

# Pro: AI-помощник для заявок в Excel

## Выбранный MCP-сервер

Использован готовый [haris-musa/excel-mcp-server](https://github.com/haris-musa/excel-mcp-server), версия 2.3.2 из PyPI. Он работает без установленного Excel и предоставляет чтение и запись ячеек. Собственный MCP-сервер в проекте не создаётся.

Подключение: MCP SDK → дочерний процесс `excel-mcp-server stdio --allow-dir <папка pro/data>`. Серверу доступна папка учебных книг. Приложение фиксирует книгу `data/requests.xlsx`, лист `Заявки`. Секреты LLM остаются на локальном сервере.

Инструменты:

- `read_range` — актуальные данные, поиск заявки, свободный ID, проверка результата; поддерживается пагинация.
- `write_range` — новая строка либо единственная ячейка статуса.
- `create_workbook`, `format_range`, `set_sheet_layout` — первоначальное создание и оформление примера.

LLM видит три предметных функции: `read_requests`, `add_request`, `propose_status_change`. Она сама выбирает действие и параметры из текста пользователя. Эти функции вызывают реальные MCP-инструменты выше; сырых произвольных записей LLM не получает. Это обычные функции MCP-клиента, а не ещё один MCP-сервер. Все чтения и изменения книги, включая создание примера и проверки, выполняются через MCP. Приложение не импортирует openpyxl/pandas. openpyxl является внутренней зависимостью выбранного готового сервера.

## Запуск

Требуются Node.js 22+, Python 3.12+ и LLM с function calling. Из корня распакованного проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cd lite
npm ci
cd ../pro
cp .env.example .env
# Заполните LLM_BASE_URL, LLM_API_KEY, LLM_MODEL
npm start
```

Откройте http://127.0.0.1:3001. Для локальной Ollama используйте настройки из README Lite. Для иного пути к серверу задайте `EXCEL_MCP_COMMAND` в `.env`. По умолчанию используется `../.venv/bin/excel-mcp-server` (Linux/macOS). На Windows укажите путь `.venv/Scripts/excel-mcp-server.exe`.

`npm run setup` создаёт исходную книгу, только если `data/requests.xlsx` отсутствует. Существующую книгу команда не перезаписывает. Пример книги включён в поставку в итоговом состоянии: 4 заявки, включая №104, статус Анны — «В работе». Чтобы начать с трёх исходных строк, задайте `REQUESTS_FILE=practice.xlsx` в .env и выполните `npm run setup`.

## Обязательные сценарии

1. «Добавь заявку от Анны Смирновой: ноутбук сильно тормозит». Приложение читает книгу через MCP, выбирает max(ID)+1 и записывает строку со статусом «Новый». Повторное чтение сверяет всю таблицу.
2. «Измени статус заявки Анны Смирновой на \"В работе\"». Показывается конкретная запись и старый/новый статус. До нажатия **Подтвердить** записи нет. Кнопка **Отмена** отменяет действие. После подтверждения приложение сверяет исходные данные, пишет одну ячейку и проверяет всю таблицу через MCP.
3. «Покажи все заявки со статусом \"В работе\"». Чтение актуальной книги и фильтрация; отображаются записи и количество. **Обновить таблицу** снова читает книгу через MCP и показывает все заявки.
4. «Измени статус заявки №999 на \"Готово\"» — запись не найдена, записи нет.
5. «Добавь новую заявку от Дмитрия» — уточнение проблемы без записи.

В журнале интерфейса и консоли видны реальные названия MCP-инструментов, аргументы и результаты. Книга — источник истины. Ответы об успешной записи формируются только после проверенного MCP-результата.

Подтверждение связано с сессией браузера. Новое текстовое сообщение аннулирует старое предложение. Если книгу изменили после предложения, требуется новый запрос. Внутри одного процесса записи сериализованы; не запускайте несколько экземпляров Pro над одной книгой и не редактируйте файл вручную одновременно с запросом записи. Это учебное локальное приложение, без общей транзакции с настольным Excel.

## Проверка

```bash
npm run check
npm test
```

Тест использует настоящую LLM и MCP, создаёт отдельную книгу `data/test-<время>.xlsx` с исходными тремя заявками и добавляет учебную заявку №104. Основную книгу не изменяет. Он проверяет отсутствие записи до подтверждения, неизменность остальных данных, две заявки «В работе», отсутствие записи для №999 и уточнение проблемы Дмитрия. Журнал: `evidence/verification.json` и `evidence/verification.log`. Созданные тестовые книги можно удалить после проверки.

Установленные зависимости Python зафиксированы в корневом `requirements.txt`; Node — в `lite/package-lock.json`. Для доступа к удалённой LLM нужен интернет; локальная Ollama после загрузки модели работает без внешнего LLM API.
